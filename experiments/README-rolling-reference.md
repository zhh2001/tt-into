# 时间门控编排的有限闭环模型

首轮记录为 [n2-rolling-01](../data/rolling-reference/n2-rolling-01/manifest.json)。这是合成事件模型，不是 BMv2 网络测量。候选版本 6 的 12 B 基础头和 12 B 记录尚未部署 P4。原 P4、历史测量与旧重放器保持独立。

## 决策与观察

两条固定业务路径为 1→3 和 2→3，三个出口队列对象共享缓存。四个流—节点键各选择禁用或 50/200/1000 ms 阈值，共同每包容量 K=1。成功插入才更新 TT-INT 门控，禁用、改阈值和重新启用均不清空最后成功时间。关闭全部键仍承担基础头。

管理通知在到达后提供目标间隔、权重和活跃状态，不提供未来业务或故障标签。动态读/写只能在当前时刻后发出。写入分别记录请求、生效和确认，阈值先于开通写入，各字段不称原子操作。版本用于确认排序，本模型没有额外实现数据面版本比较或失败回滚。

在线函数只接收已经收到的报告、已返回源计数、已确认配置、缓存和需求通知。真实生成时间、完整业务轨迹、丢报标签与执行器寄存器用于离线检查。每流的两次付费计数返回后才计算响应间计数差分 EWMA，系数 0.5。

首个预测器使用均匀机会、名义包长 120 B、每跳 20 us、egress 5 us 和报告延迟 1 ms。缓存以有效样本接收新近度播种，门控从合法报告与名义延迟估计，不把本地时间戳当成跨节点年龄真值。预测器没有恢复实际突发、相位或丢失过程。

## 四种方法

| 方法 | 选择方式 |
| --- | --- |
| static | 在两个训练种子穷举 256 个联合许可/阈值配置，选定后冻结 |
| feedback | 根据付费计数和收到的报告估计费用占比，统一上调或下调已启用键的阈值 |
| local | 用忽略包容量的局部时效收益评分，费用预测仍遵守共同 K=1 |
| joint | 用容量敏感的共同预测损失评分，联合更改许可与阈值 |

静态选择按最大训练预算超限、平均损失、启用键数和配置编码排序。所有动态方法从同一个训练配置出发。静态方法不做无用途的计数轮询，收到的管理通知按共同口径计费。

局部和联合策略从当前配置、训练配置、统一升降阈值出发，检查单键更改和两键交换，最多评价 48 个配置，每周期最多 6 次更新 RPC。先修复预测预算，再优化损失，不保证网格最优。统一反馈只调已启用键，没有联合重新授权。以上为共同接口上的原型参考方法，不是文献方法的完整复现。

## 任务、费用与运行

评价损失为活跃区间内的加权连续 min(生成 AoI/目标间隔,4)，未知状态取 4。使用全部任务的权重与时长作为分母，共享对象不重复计收益。有效接收新近度另外计算，不替代生成 AoI。

7 个场景为稳定、同均值突发、共享对象重点监测、流量/需求切换、稀疏停流、导出延迟/丢失和基础头预算不足。每场景两档预算。训练种子为 11/29，保留种子为 101/211/307/401。参数先固定，测试不参与选参。每次 10 s，前 2 s 原样运行预热，测量 [2,10) s，不免费预置缓存。

费用分别计算逐链路 IPv4 遥测增量、Ethernet 导出尝试和控制接口序列化字节。导出使用最小帧补齐，不含 FCS，丢失尝试仍计费。API 字节不与帧字节相加。窗口平均预算和每秒实际超限均保存，没有硬逐窗口监管。

| 控制操作 | 请求/回复字节 | 依据 |
| --- | --- | --- |
| 阈值写入 | 94/30 B | 本机绑定序列化，与既有网络写 RPC 记录核对 |
| 许可写入 | 89/30 B | 使用已有容量寄存器名称对应序列化，与既有写 RPC 核对 |
| 源计数读取 | 81/40 B | 本机绑定序列化参照，本轮没有读取网络测量 |
| 管理通知 | 128/0 B | 预声明模型消息，尚无实际传输测量 |

共同控制预算为 1200 B/s。路由和表安装、管理协议封装、连接、完整状态存储及宿主开销尚未成为部署费用，不能声称已经得到全部网络控制成本。预测运算时间只是 Python 实现的主机计时。

## 复现

需要 Python 3、本机 BMv2 Standard/Thrift 绑定、Matplotlib、NumPy 和 pdffonts。费用核对还读取已公开的历史写入记录。所有输出目录必须是新的目录，避免覆盖原始结果。

先执行：

~~~bash
python3 -m unittest discover -s tests -v
python3 experiments/run_rolling_reference.py \
  --output data/rolling-reference/新的运行目录
python3 experiments/check_rolling_reference.py \
  --run data/rolling-reference/新的运行目录
python3 experiments/analyze_rolling_reference.py \
  --run data/rolling-reference/新的运行目录 \
  --output data/rolling-reference/新的分析目录
python3 experiments/plot_rolling_reference.py \
  --run data/rolling-reference/新的运行目录 \
  --output figures/rolling-reference/新的绘图目录
~~~

静态训练保存全部 7168 个配置/种子结果。224 次保留执行分别保存输入、逐事件输出、在线视图、决策、候选评分、调用和各周期成本。执行源文件与输入输出摘要分别留档，失败时保存状态与异常。原运行时单元记录为 166 项，随后加入独立检查器破坏测试，最终 171 项检查通过。

独立检查器不导入策略或事件引擎。它由输入 egress 顺序和配置生效时间重建门控，核对线格式、逐链路传播、导出尝试、读写账本、报告/通知/确认前缀、完整任务分母和分段梯形积分。最终核对 31680 个包执行实例、2240 次决策和 94020 项费用条目。

仅 stable/shared_priority、高预算、seed=101 作两个额外诊断：2 s 时合法代理的全网格评分，以及事后未来已知的静态配置枚举。这些不是在线策略，也不是动态最优上界。

## 首轮结果

全部 224 次执行中，196 次满足总测量窗口预算。静态、反馈、局部和联合分别为 52/56、45/56、48/56、51/56。预算不足的低档场景中四种方法均超限，即使禁用全部采样，共同链路基础头仍需 192 B/s，超过 150 B/s。

联合方法未显示稳定优于充分调参静态 TT-INT。重点监测低预算的平均损失下降约 0.00444，同时增加控制费用。突发低/高预算的平均损失分别增加约 0.41004/0.10110，同时导出减少，不能仅凭一个指标宣称总成本前沿改善或全面退化。切换低预算联合方法有 1 个种子总窗口超限。

联合方法的突发新近度预测平均绝对误差约 0.427，切换场景有 26 个预测达标、实际超限周期。两项代理网格检查的搜索损失差距分别为 0 和约 0.01291。当前证据不足以把无收益主要归因于搜索，更需要核对机会及费用预测。

四个种子只提供有限模型诊断。配对差值保存全部种子及双方实际可行的子集，子集不能替代完整结果。bootstrap 区间不作为论文显著性结论。实际成本前沿仅比较本轮方法/预算产生的点，不代表全部配置的 Pareto 前沿。
