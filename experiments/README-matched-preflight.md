# 共同配置网格与自有控制费用

本轮完成性能比较前的接口验收，没有运行新的训练、校准或保留业务矩阵。最终数据为 [n3b-preflight-03](../data/matched-reference/n3b-preflight-03/manifest.json)，独立核对见 [验收记录](../data/matched-reference/n3b-preflight-check-01/verification.json)。全部 231 项单元检查通过。

## 共同配置

四个流—节点键各选择禁用或 50/100/150/200/400/600/800/1000 ms。静态和动态接口共用完整的 6561 个配置，保持 K=1、字段、身份格式及固定路径一致。动态有限搜索上限仍为 48 个候选，每周期最多 6 次字段写入。完整集合与有限求解能力分开记录，不能把动态搜索称为网格全局最优。

保留 static、feedback、local、joint、phase_joint、uniform_guard、phase_guard 和 phase_local_guard 八种方法。80 次接口烟测使用 N3 普通版已有的十个合法观察视图，每种方法调用十次，没有重新训练静态配置或部署烟测输出。初态参照为该视图的实际确认配置，仅用于接口验收。

普通版闭环约 7 s 的一个视图另做 6561 候选穷举。联合与局部的有限搜索都评估 38 个候选，排序结果与各自穷举参照相同，配置为 [off,50 ms,off,50 ms]。该视图仅有对象 3 活跃且预算宽松，最优结果是保持当时配置。它不证明一般搜索质量、真实未来最优或监测性能优势。

## 费用与可用时刻

ControlLedger 只接收自己完成的 API 调用及实际收到的本地通知。请求按调用开始、回复按调用返回归因，完整字节长度在返回后可用。因此窗口可以只包含请求或只包含回复，但策略不能提前看到尚未返回的实际回复长度。调用边界是序列化归因约定，不是精确帧发送时间。

延后配置确认不延后计费。失败调用和读取实际状态的核对分别计费。重复导入同一费用项不重复计费，冲突身份报错。诊断读取、诊断寄存器清零、链路抓包和仿真费用真值不进入合法控制费用视图。真实初始化与门控清零保留，按各自时刻决定是否进入测量窗口。

| N3 实测调用 | 请求 B | 回复 B |
| --- | ---: | ---: |
| 阈值写 | 94 | 30 |
| 许可写 | 89 | 30 |
| 源计数读 | 81 | 40 |
| 受控错误写 | 97 | 41 |
| 受控错误读 | 86 | 40 |
| 许可状态核对 | 77 | 40 |

费用参照直接来自 N3 普通和诊断日志，受控错误长度只对应这两个指定错误，不能推广到断连、超时或任意异常。

API 序列化字节与 UNIX 通知有效负载使用不同层和独立预算。本轮接口值为 API 1200 B/s、本地通知有效负载 128 B/s，后者是声明的预算上限，不是通知消息长度或管理网络帧。通知编码沿用实际发送接口，每条长度来自实收字节；不再套固定 128 B 消息假设。

MatchedProxy 用已知自有 API 费用计算剩余控制预算，旧控制预测历史仅保留为审计辅助，不再用于扣减。下一周期预测计入计划源计数和字段写，已经收到的通知不会再次预收费。未来未知通知与异常回复仍不能准确预知，通知超限保留为独立债务。带内基础头、计数尾段和未收到导出仍是估计，没有硬预算保证。

## 独立验收

普通和诊断各五类 N3 案例共核对 260 个决策费用前缀。独立检查器不导入策略或账本，从原始调用及通知直接重建时间、长度、可用性和窗口费用，并核对候选调用、限额和求解排序，共完成 17377 项核对。

| 案例 | 每版本测量窗口 API B | 本地通知有效负载 B |
| --- | ---: | ---: |
| identity | 968 | 0 |
| continuous | 2422 | 0 |
| partial_failure | 2803 | 0 |
| counter_wrap | 968 | 0 |
| causal_loop | 2293 | 192 |

每案例窗口沿用原运行声明，前四类是 [0,运行结束) s，causal_loop 为 [2,10) s，不能按相同运行时长比较这些总费用。归档 3720 个案例归因条目会重复引用同一运行调用，以便分别核对每个窗口，不代表 3720 个独立调用。源码、输入摘要、前缀与完整候选均留档。

新增检查覆盖未来后缀、跨窗口请求/回复、测量右边界、重复费用、失败与核对、通知分层、已知债务和数据破坏。网络行为及原始数据保持原 N3 记录，本轮没有新增网络运行。

## 复现与后续接口

~~~bash
python3 -m unittest discover -s tests -v
python3 experiments/run_matched_preflight.py \
  --n3 data/into-validation/n3-validation-01 \
  --output data/matched-reference/新的验收目录
python3 experiments/check_matched_preflight.py \
  --run data/matched-reference/新的验收目录
~~~

输出目录必须不存在。需要既有 N3 公开数据，Python 3 和本机 BMv2 绑定；本轮不启动 Mininet 或 BMv2。

已预留校准 1301/1423、保留 1601/1723/1871/1999，但未生成或执行这些业务输入。下一项工作是将该费用层接入完整事件执行，去掉旧事件层将通知计作 Thrift 的假设，明确通知实际可用、初始化与共同预热，再冻结九场景、两预算的训练/校准/保留矩阵。旧 20 us/100 us 控制生效与回复仅是合成先验，不能当成 BMv2 真实延迟。

该验收为因果费用和共同配置接口证据，不提供静态与动态方法的公平性能排名。
