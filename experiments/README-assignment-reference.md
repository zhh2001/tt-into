# 准确分配参照与因果时隙适配

实现固定路径下 [D-INTO](https://doi.org/10.1109/TNSM.2025.3530432) 的 P3 和 [INTOPP](https://doi.org/10.1109/LCOMM.2019.2946562) 的单时隙依赖分配。原目标与本项目共同年龄任务的适配分开核对。本目录的运行是条件事件模型，不是 BMv2 网络测量。

## 分配模型

代码位于 `src/orchestration/assignment_reference.py`。

- D-INTO 保留逐项唯一指派、路径资格、每流字节容量及 `Q*Delta - V*In`。换流计撤销和新增两次项长度，虚拟队列递推为 `max(Q + Delta - Delta_avg, 0)`。Delta 不能用作真实控制字节或物理队列积压。
- INTOPP 保留同节点空间依赖、每流容量及逐项唯一指派。`native_intopp_dependencies` 为每个空间组生成各节点的完成变量，时间组同时属于空间组。原式的时间完成数仅统计各自 `Hf > Tf` 的流，目标中的时间变量按节点数量重复计权。
- Hf 在接口中解释为经过时间，等于期限时尚未严格过期。未知状态显式用 `None`，不假定已经新鲜。原文的定义文字与过期比较存在歧义，此解释属于实现约定。
- 原式计数变量的 `N+` 写法按允许 0 解释，用于表示未采集的依赖。否则空采集或无到期流无法赋值，不能支持这些必要输入。
- `temporal='count'` 保留原式的数量判断，同类项在不同节点可能共同计入完成数。`temporal='distinct'` 是要求各类型齐全的较强适配，不能称作原公式。
- 原目标有多个最优解时，依次最小化指派变更量和按项排序的流优先序，未分配记为 0。默认顺序为流号，也可给定完整排列。这只处理平局，不改变原目标。MILP 不接受非零相对最优差距，未证明最优时运行失败。小规模事件适配使用准确枚举，未实现 Fast-LR 或在线聚类。

接口允许不同项长度。原文同类型大小一致，最终原模型审计也保持这一设置。60 个预声明实例分别检查 P3、原计数依赖及 distinct 变体，共 180 次模型对照。独立穷举不调用被测目标、可行性或依赖函数。原始实例、逐流状态、期限、指派和目标值都保存在 `model-audit.json`。

## 共同事件适配

`slot_reference.py` 使用三条固定流：F1 经过 S1、S3，F2 经过 S2、S3，F3 仅经过 S3。每节点的共同状态记录为 12 B，包头为 4 B。每流分配容量取 `Bf=12*K`，其中 K 为 1 或 2。包速率、包头、共享链路和导出成本不在这一原分配容量式中，另按整次运行计费。

指派转为既有 P4 参数的目标：被指派的节点与流使用阈值 1，其他索引使用容量 0。原成功门控状态保留。TT-INT 对照直接调原有逐流阈值及静态流授权。D-INTO 收益网格包含固定任务权重和基于已收报告年龄的管理员收益，后者是适配，不是熵学习。

INTOPP 年龄适配使用三个单项应用和全局对象的最新已收报告，原逐流组状态在单独的原模型审计中检查。该适配没有联合数据聚类，也没有将多种遥测值的异常检测纳入实验。提前采样变体另给 50、100、200、300 ms 余量，不把只使用已过期规则的版本作为唯一对照。

控制器只看到已经到达的报告。生成时间来自统一理想时轴，过期报告不会回退最新状态，没有证明跨交换机时钟同步。预热为 800 ms，测量为 2400 ms，完整数据费用包含预热。每 100 ms 决策，需求变更时另有通知事件。变更需求在其开始时才可见。

生效延迟固定为 2 ms，是模型输入。业务轨迹在决策附近留有给定空隙，保证配置切换不跨在途包。该前提没有经过本轮网络测量，不适用于任意连续业务或跨节点原子更新。连续年龄用全部送达报告积分，任一阶段存在正违约时间的对象不算完整履约。

## 调参与测试

每种容量都使用相同的拓扑、种子、需求与预算。七类场景为到包抖动、短突发、低流量、期限变更、报告延迟、报告丢失和预算不足。源端抖动范围为正负 20 ms，正常报告延迟为 100–500 us，延迟场景为 60–140 ms，丢失概率为 0.15。完整时间与丢失状态保存在输入轨迹，不删去不利样本。

训练种子为 0–7。每个容量和方法跨全部训练场景选一个配置，按平均预算内履约权重、违约比例、数据费用、API 费用及网格索引依次排序。TT-INT 有 200 个配置，D-INTO 有 96 个，INTOPP 原过期适配有 3 个，提前适配有 12 个。三个分配方法同时调 `(1,2,3)`、`(2,1,3)`、`(3,1,2)` 平局选流顺序，避免固定较小流号而使某个对照受损。不同场景等权只是本次诊断约定，不代表应用分布，也不证明任意 TT-INT 控制器的最优性。

最终 `causal-slots-06` 使用新的保留种子 300–319。保留数据不参与参数选择。每场景 20 个种子，四个方法和两个容量共享同一输入，共 1120 次保留执行。另有 34832 次训练配置执行。方法和容量之间存在配对关系，不能把这些执行数当作独立统计重复数。

费用预算只评价整次执行，未实现在线预算监管。预算失败时保留全部包、报告与指标，预算内履约权重记为 0。该权重是事后评价，不是执行前承诺的任务接纳。另放宽项数、门控与预算检查及时报告机会，它仅给必要上界，不是可免费部署的策略。

## 控制费用口径

校准来源为已有普通版 `admission-margin-ordinary-01` 的真实 RPC 记录。单独冷安装的 69 次调用共 8958 B，包含共同状态安装及五个初始阈值。初次启用和后续变更额外计费，`max_count` 写入为 119 B，`time_threshold` 为 124 B。这些是序列化请求加回复的校准长度，不是本轮捕获的网络帧。

被动读取已收遥测报告没有额外轮询，报告已列入导出成本。路由 CLI、TCP 握手与帧、主机进程和实际处理时间没有包含在 API 层账本中。因此不能把这一账本称为全部部署成本。API 字节与带内、导出帧字节分列，不跨层相加。

## 复现与独立检查

从项目根目录运行，无须 root：

```bash
python3 -m unittest discover -s tests -v
python3 experiments/run_assignment_reference.py \
  --output data/assignment-reference/new-run
python3 experiments/check_assignment_reference.py \
  --run data/assignment-reference/new-run \
  --output data/assignment-reference/new-audit/checks.json
python3 experiments/plot_assignment_reference.py \
  --run data/assignment-reference/new-run \
  --output figures/assignment-reference/new-run
```

输出目录必须不存在。运行清单保存参数、源码摘要、实际源码快照、Python/SciPy 版本、主机负载、状态和运行时长。大 JSON 无损压缩为 `.json.gz`。独立检查器重新计算前缀门控、栈序、链路字节、导出填充、寄存器目标、连续年龄和预算，同时检查训练网格完整性、所选参数及保留种子隔离。

最终记录为 [causal-slots-06](../data/assignment-reference/causal-slots-06/summary.json)，核对记录为 [audit-06](../data/assignment-reference/audit-06/checks.json)。图同时导出 [PNG](../figures/assignment-reference/heldout-06/heldout-task-feasibility.png)、[PDF](../figures/assignment-reference/heldout-06/heldout-task-feasibility.pdf) 和统计 CSV。字体为真正 Times New Roman，PNG 为 300 dpi，PDF 嵌入 TrueType。图中的须线是 20 个保留种子的最小、最大范围，不是置信区间。

最终 280 组配对输入中，四种所选方法的采样、已收报告、年龄、数据及 API 费用全部一致。这是所声明模型和训练网格下的观察，不表明方法在任意拓扑、任务、收益或业务下都等价。

## 历史运行

`causal-slots-01.tar.gz` 完整保留第一次失败运行。狭窄目标锁定区间在零容量、负目标情况下触发当前 HiGHS 的预处理不可行判定，改用已求得离散目标值的等式后通过独立穷举，另有对应单元检查。它是实现数值问题，不是论文模型不可行。

`causal-slots-02.tar.gz` 保留第一次完成的全量未压缩结果，`causal-slots-03` 是仅改变无损压缩格式的重执行。两者轨迹、配置、逐次执行、原审计和统计完全一致，见 `audit-03/packaging-check.json`。它们的 INTOPP 审计只覆盖全局到期及给定权重的形式，不代替最终原式逐流到期筛选审计。04 补齐这一原模型接口，事件网格不变，保留种子重新划分。历史运行不合并成额外统计重复。

04 的原分配审计路径有一个不在声明节点集合中的中间跳。05 去除该跳，使原式节点重复权重与物理节点集合一致，事件输入及逐次结果与 04 相同。05 的准确分配平局仍固定按流号，造成部分与 TT-INT 调参结果的差异。06 将平局顺序纳入共同训练，使用新的保留种子，不沿用此前已观察的测试集。03、04 的图是对应版本的历史诊断图，不当作最终基线差异。

历史归档逐文件核对与源目录一致，摘要见 `audit-03/historical-archives.json`。解压到新的目录后可核对其中原始清单及源码。没有覆盖原始运行或删除不利结果。
