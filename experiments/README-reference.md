# 共同状态与事件参照复现说明

这组文件完成状态格式与测量口径验证，并提供小规模离线参照。真实网络数据位于 `data/state-validation/`，合成事件数据位于 `data/orchestration-reference/`。当前没有 TT-INTO 在线优化器，也没有将参考策略的违约比例表述为 BMv2 编排性能。

## 状态格式和采样语义

扩展版使用本地实验 EtherType `0x88B6`，与原核心 `0x88B5` 区分。共同基础头为 8 B，按顺序包含 Count、InitTTL、Version、Metric、AllowMask、Seen 各 1 B 和 Epoch 2 B。记录为 20 B，包含 SwitchID 1 B、HopNum 1 B、生成时间 6 B、队列包数 4 B、随机选择键预留 8 B。

Version=1、Metric=1 表示前向出口端口 2、默认单队列的出队深度快照。`deq_qdepth` 的单位是包数，不是字节数。生成时间采用 `egress_global_timestamp`，表示进入 egress 处理的时刻。队列值对应此前的出队事件，不表示任意时刻直接读取到的当前队列长度。门控继续使用 `ingress_global_timestamp`，两种时间不能混为一个变量。字段语义依据 [BMv2 官方说明](https://github.com/p4lang/behavioral-model/blob/main/docs/simple_switch.md)。

当前 P4 只执行前序的时间门控和前缀插入。AllowMask=255、Seen=0、Epoch=0、SelectionKey=0 是预留字段，尚未实现权限选择或随机替换。编译栈上限 8，实际检查使用三个采样节点和一个独立 sink。将记录中 SwitchID 映射为任务，只在该固定单出口实验域内有效。

所有事件对照承担同一 8 B 头和 20 B 项，以隔离算法行为与格式差别。这个格式不是每种对照的最小开销，特别是无需随机键的方法也承担预留字节。正式性能比较还需补各方法原生格式及取消预留字段的消融，不能用共同格式推断最佳部署成本。

## 网络检查与时钟区间

编译和验证：

```bash
python3 experiments/build_state.py
python3 experiments/build_state.py --diagnostics
sudo python3 experiments/run_state_validation.py \
  --output data/validation-runs/state-check
sudo python3 experiments/run_state_validation.py --ordinary \
  --output data/validation-runs/state-ordinary-check
```

输出目录必须尚不存在。普通版与诊断版分别运行 90 个业务包，检查两个 UDP 流、端点恢复、逐跳状态、非空克隆、MTU 边界和限速突发。两个实际运行均完整交付 90 包并导出 86 个报告，诊断版最高测到 18 包的队列快照。每个运行的 446 个输出 IPv4 帧均通过校验和及 1500 B MTU 核对。

分析只读原始目录，输出可公开数据：

```bash
python3 experiments/analyze_state.py \
  --run data/validation-runs/state-check \
  --output data/state-validation/state-check
```

只有重生成同一运行的派生数据时才使用 `--refresh`，不覆盖原始测量。源码摘要、输入清单、发送事件、收报时间、PCAP 和派生文件摘要均保留。

BMv2 进程各自从零计时，当前不使用 PTP。16 个训练包分别位于工作负载前后，48 个中间包留出检查。对节点 i 的偏移 Oi，由宿主发送前时间 S、记录时间 G、宿主内核收报时间 R 构造 `S-G-δ ≤ Oi ≤ R-G+δ`，取训练包交集。预先固定 δ=101 μs，其中 100 μs 是宿主时钟变化条件，1 μs 为量化余量。发送过程同时记录 wall/monotonic 配对，若观测变化超过 100 μs 则停止导出。

留出包用该区间与发送、收报括区的交集检查相容性，共 144 个节点样本。实际节点偏移区间宽度分别为 1.604399、1.614399、1.639399 ms。它们是恒定时钟偏移及有界变化假设下的区间，不是硬件同步精度，也不证明运行中所有时刻的时钟误差。训练探针的发送、遥测和分析有成本，不能作为在线策略的免费观测。

年龄在实际工作负载窗口上积分，保留窗口开始前已经收到的第 8 个训练包作为初始样本，不人工将年龄置零。生成时间上下界分别给出年龄与违约比例上下界。当前 100 ms 期限下三个任务的违约区间均为 `[0,0]`。这仅验证采集时间口径，不是异质任务优化结果。

## 六种事件参考策略

| 名称 | 执行逻辑 | 实现范围 |
| --- | --- | --- |
| `tt_prefix` | 每流门控，按实际跳序使用剩余容量 | 共同格式下的固定阈值 TT 核心适配 |
| `shared_prefix` | 同对象跨流共享成功门控时间，再按跳序插入 | 共享门控的容量适配，不含反馈控制 |
| `uniform_reservoir` | 合格记录具有独立等权随机优先级，保留最多 K 项 | 实数事件参照，未实现 P4 随机选择 |
| `weighted_reservoir` | 按任务权重生成随机优先级，保留最多 K 项 | 实数事件参照，未实现有限精度键 |
| `rotation` | 入口按包序轮转许可任务，合法且到阈值才插入 | 固定轮转权限参照 |
| `static_flow` | 给每条流固定非空任务子集，子集中仍执行门控与容量检查 | 静态任务授权及逐节点阈值枚举 |

蓄水池键使用 `-ln(U)/w`，较小者优先。等权得到均匀随机子集。加权采用顺序无放回选择的权重语义，K>1 时不能把最终入选概率简单写成 `K*w/Σw`，参见[作者对加权抽样的说明](https://arxiv.org/pdf/1012.0256)。

回放器按各节点的生成事件顺序处理。只有实际插入才更新时间门控，容量拒绝或随机拒绝不更新。下游替换上游记录不会撤销此前插入成功，上游记录在前段链路已消耗的字节仍计费。这些是当前适配语义，不代表所有已有系统的原生行为。

当前没有完整复现 INT-label 的反馈控制、INTDirector 的 Dev 筛选与路径扩展、Sel-INTO 或 SD-INT。六种参考策略足以检查简单反例是否已被基础对照解决，还不能替代最终论文的强基线集合。

## 连续年龄和成本

收到报告后仅保留最新生成时间，旧报告不回退缓存。两次有效更新之间按线性年龄精确积分，违约用连续时间比例，不用包或检查点数量比例。未知状态全部计入违约，若其质量超过相应尾部概率，P95/P99 为 JSON `null`，表示无有限值。未知占据非零时间时整体平均年龄也为 `null`，另给已知部分的均值。

每条采样节点到后续节点的链路分别计算附加字节。基础头即使没有记录仍为 8 B，每项携带后为 20 B。采集报告是 Ethernet+IPv4+基础头共 42 B 加各项记录，只有非空报告才导出。字节不含 FCS、前导码和物理层间隔，未计原业务字节。sink 到业务端已剥离遥测，该链路附加字节为零。

当前预算是整个输入轨迹及其全部报告的总量，包括年龄窗口结束后到达的在途报告，不是滑动窗口或逐时刻带宽约束。静态回放窗口内不更新控制规则，因此控制字节为零。初始安装、校准探针和优化计算未计入在线部署成本，正式扩展须单独计费。

## 离线 MILP 和预实验

MILP 固定阈值、到包与生成机会、报告延迟和无丢失条件，未来包全部已知。二元变量分别表示最终选定记录、非空报告和任务接纳。容量与逐链路预算均按真实字段宽度约束。门控冲突使用 ingress 时间差，硬期限使用生成时间与收报时间。窗口起点、候选到达左极限及终点共同约束硬期限。先最大化接纳权重，再在最优权重下最小化成本，求解状态与成本最优状态分别保存。求解接口见 [SciPy 官方文档](https://docs.scipy.org/doc/scipy-1.11.4/reference/generated/scipy.optimize.milp.html)。

这个参照允许预知未来并自由决定逐包权限，只选择最终保留的记录，不发生随机替换，不能直接作为可部署策略，也不能据此证明在线算法最优。数学模型中的 θ=0 表示无门控限制，真实 P4 的零寄存器仍表示默认阈值。公开预实验网格均采用正阈值。

运行需要 SciPy 1.11.4、NumPy、Scapy、Matplotlib 和 Times New Roman：

```bash
python3 -m unittest discover -s tests -v
python3 experiments/run_orchestration_reference.py \
  --output data/orchestration-reference/本次目录 \
  --figures figures/本次目录
```

四个合成场景分别为同相、错相、300 ms 导出延迟和基础头预算不足。每条流为 5 pps，三个任务期限为 250、450、650 ms，权重为 3、2、1，K=1，年龄窗口 1.2 s。共同初始已收样本生成于 -1000 μs，窗口门控初始无成功状态，这是明确给定的合成输入条件。它不代表已经测得的网络预热状态。

所有策略都枚举五个统一阈值以及四档逐节点阈值的笛卡尔积，静态流授权另枚举合法的非空节点子集。随机方法使用 20 个种子。同一轨迹也用于调参，结果属于乐观的参考筛查，正式预测和部署评价需要分离训练与测试。每场景保存 6348 个试验，共 25392 个，另有 20 次 MILP 求解。这些是合成配置试验数，不是独立 BMv2 运行数。数据入口是 [reference-02 摘要](../data/orchestration-reference/reference-02/summary.json)。

同相、错相场景中，逐节点调参后的共享门控和静态流授权都满足 3/3 任务，连续违约比例为零，总成本为 1572 byte-hop。各方法拥有相同预算上限，但实际支出不同，不把它称为实际开销完全相等的比较。图只展示参考筛查，[PNG](../figures/orchestration-reference/reference-baselines.png)与 [PDF](../figures/orchestration-reference/reference-baselines.pdf)均为 Times New Roman，PNG 为 300 dpi。

300 ms 导出延迟下，离线模型最高只能接纳权重为 2 的任务，不能通过减小时间阈值满足 250 ms 的任务。头部预算不足时，仅必付基础头已超限，所有固定封装参照均不可行。结论以当前固定封装和给定初始状态为条件，不排除关闭部分包封装或改变格式后的可行性。
